# Architecture of the agent office

The office is a folder tree. Each folder is a room with one purpose. Each room can have its own `AGENTS.md` and its own `mail/` box.

## Rooms

| Room | Folder | Purpose |
|---|---|---|
| Entrance | `README.md` | Notice for anyone arriving. How the office works. Created by `init.py`; edit it for your office. |
| Management | `management/` | The administration manager. Guide to the structure, registry, tools, diary and lessons. A dashboard or calendar is an optional addition you build yourself. |
| Departments | `departments/<dept>/` | One folder per department. Its work, rules, memory and projects. |
| Staff | `staff/` | `roles/<role>/ROLE_CARD.md` and resignation letters. Presence is recorded in `management/registry/presence.json`. |
| Canteen | `canteen/` | General chat and board. Only messages for everyone. |
| Library | `library/` | Readable catalog (`CATALOG.md`, generated) and reference material. Manuals go in `library/manuals/` (create it when needed). |
| Exchange | `exchange/in/`, `exchange/out/` | Hand-over point between the owner and the office. |
| Archive | `archive/` | Old attempts, compressed and verified, with restore notes. |
| Inspectorate | `inspectorate/` | Office of the external reviewer. Reports and diary. |
| Mail | `<room>/mail/` | One mailbox per department and service room. |

## Layered AGENTS.md

- The root `AGENTS.md` holds the rules for every agent in every room.
- Lower folders can have their own `AGENTS.md`. They add to the root file. They never replace it and never copy it.
- An agent reads every `AGENTS.md` from the root down to the folder where it works.
- A level adds only the rules of that level. Do not copy a department's rules into another.
- Rules are numbered (R01, R02, ...). Other files point to them by code.
- Each rule has three parts: the rule, the exceptions, the check (a guard, a tool or "judgment").

## Mailboxes and canteen

- Requests, answers and targeted notes go to the mailbox of the recipient: `<room>/mail/`.
- A message has a sender, a recipient, a status (open or closed) and a body. Notes are born closed.
- Agents read new mail with `post.py read --mailbox <room> --new --reader <badge>`. This shows everything since the last read, notes included.
- Open requests are listed with `--open`.
- The canteen is only for general messages: advice for all, announcements. Never use it for a task meant for one person.

## Exchange: in and out

- `exchange/in/`: the owner drops material here. The office processes it: look at it, move it to the right room, add it to the library if it is knowledge, log it in `exchange/RECEIPTS.md` (created by `init.py`; what, from where, where it went). The folder must end up empty.
- `exchange/out/`: deliveries for the owner. Only copies. The original stays in its room.
- Copies in `out/` expire after a fixed time. The policy of the package is **7 days by default; change the number in your root `AGENTS.md` if you want another period**.
- The package ships **no expiry script or timer**: the policy is a rule for agents (judgment). If you want automatic deletion, add a daily job of your own that deletes only top-level items of `out/` older than the period, logs each deletion with its SHA-256, never touches `in/`, and offers a preview mode.
- A written exception, with a reason, can keep an item longer.

## Library

- The library has a catalog: `management/registry/catalog.json` (the data) and `library/CATALOG.md` (a readable list generated by `library.py add`, so it appears after the first entry). Each entry has an id, title, path (checked to exist when added), department and tags.
- Before searching elsewhere, search the catalog: `library.py search <words>`. It prints the entries whose text contains all the words. It does not suggest the archive: look there yourself when the catalog has no answer.
- If nothing is found, search outside, then add the entry to the catalog.
- Shared technical manuals live in `library/manuals/`. Departments link to them from their own `AGENTS.md`.
- `library.py check` lists entries whose file has moved or vanished and exits with 1 if any is missing. There is no field for who verified an entry; note it in the title or in the manual itself.

## Archive

- The archive holds old attempts that are no longer used but may be useful.
- Each snapshot is a compressed file (zip or tar). After creating it, verify it: list and test the archive, compare hashes of a sample of files, then delete the source.
- Each snapshot has a restore note: what it contains, date, how to unpack, where to put it back.
- When the catalog has no answer, look in the archive.

## Inspectorate

- The inspector is an external reviewer. It has its own room with reports and a diary.
- Outside its room it reads only. It may write elsewhere only when the owner says so, explicitly.
- Its reports go to management and the owner. Departments answer through their mailbox.
- It looks at facts: rules followed, estimates against actuals, delivered files against requests.

## Room projects and `project.json`

- A project has its own folder inside a department, with a `project.json` status file.
- Typical fields: `name`, `owner_dept`, `status` (open, paused, closed), `opened_on`, `closed_on`, `milestones` (title, date, done), `next_step`, `lessons_file`.
- Dates are real dates read from the system clock.
- An agent that resumes the project reads `project.json` first, then the project's `LESSONS.md`.
- When the project ends, set `status` to closed and fill `closed_on`. Management keeps the statistics.

## Where notes go (hierarchy)

| What | Where |
|---|---|
| Rules valid everywhere | Root `AGENTS.md`. Only there. |
| Rules and knowledge of one department | `departments/<dept>/AGENTS.md` and `departments/<dept>/memory/` (one fact per file, index in `memory/INDEX.md`). |
| Shared manuals | `library/manuals/`. |
| Experience of a job | `staff/roles/<role>/ROLE_CARD.md`. |
| State of a project | `project.json` of that project. |
| Working notes for resuming a chat | The diary of the room or role. For management: `management/DIARY.md`. |
| Owner corrections | `LESSONS.md` next to the work, and "mistakes not to repeat" in the role cards touched. |

## rooms.json

`management/registry/rooms.json` lists every room that has a mailbox:

```json
{"rooms": [{"id": "management", "path": "management"}, {"id": "design", "path": "departments/design"}]}
```

## Glossary

- **Badge**: the id an agent gets when it starts working; every action is logged under it.
- **Clock-in / clock-out**: recording when an agent starts, changes room, rests or leaves.
- **Shift / quota**: the usage budget of a model team (e.g. a 5-hour session window and a weekly window).
- **Estimate**: a written forecast of the quota a task will use, made before the task starts.
- **Warden**: an automatic check (a hook) that warns about or blocks an action that breaks a rule.
- **Blind review**: a check by a colleague who did not do the work and gets no context from the author.
